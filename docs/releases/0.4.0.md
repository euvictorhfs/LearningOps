# LearningOps Core 0.4.0

## Previous version

`0.3.2`

## New version

`0.4.0`

## Reason

Recover the richer pedagogical method from the original LearningOps design, formalize missing responsibility boundaries and add Generative-AI engineering architecture for a maintainable prompt/spec/runtime system.

## Main changes

- formal Learning Method with Socratic, retrieval, spacing, interleaving, Pareto Two-Pass, problem-based, deliberate, adversarial, transfer and metacognitive methods;
- explicit adaptive operational cycle;
- Competency Model spec;
- Curriculum spec;
- PDI spec;
- Mastery Computation spec;
- Knowledge Graph spec;
- Evidence-Based Resume spec;
- Generative AI Architecture spec with Single Responsibility and role isolation;
- LearningOps Evaluation spec for runtime regression behavior;
- ChatGPT adapter simplified to one maintenance chat (`Sistema LearningOps`) and naturally named study chats;
- Project prompt refactored into an orchestrator/role router;
- bilingual onboarding README;
- machine-valid schemas for durable competency, curriculum, PDI, evidence, mastery, checkpoint and graph records;
- stale `LearningOps-core` repository references corrected in affected specs.

## Impact

### Core

Material architecture and methodology change. The system becomes more modular: specialized specs own separate responsibilities and the Project prompt orchestrates them.

### Workspace

No learner domains, baseline values, mastery values or evidence records are changed by this release.

### ChatGPT adapter

Existing Projects should replace their Project Instructions with the 0.4.0 canonical `runtime/CHATGPT_PROJECT_INSTRUCTIONS.md` after merge.

The recommended UI convention becomes:

- `Sistema LearningOps` for installation/governance/maintenance;
- other chats named naturally after the learning field.

## Migration

No learner-state data migration is required for existing 0.3.x Workspace data.

The evidence schema is extended in a backward-compatible direction to represent external sources, substantially generated assistance, confidence, limits, counterevidence, privacy and correction lineage.

New schemas are additive. Workspace adoption can occur when those record families are first persisted or through a later governed Workspace migration if required.

## Compatibility

- existing evidence/history remains conceptually valid;
- Zero Baseline and Evidence Lineage invariants are unchanged;
- existing Cockpit zero-state semantics remain valid;
- external integrations should not assume the old monolithic learning-spec behavior; they should load the specialized spec responsible for the operation.

## Validation required before merge

At minimum review the Evaluation Spec cases for:

- maintenance vs study role isolation;
- Zero Baseline;
- assessment hint ladder;
- no metric without evidence;
- PDI/curriculum adaptation;
- Core/Workspace separation;
- GitHub capability honesty;
- context/retrieved-instruction safety.
