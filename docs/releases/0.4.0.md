# LearningOps Core 0.4.0

## Previous version

`0.3.2`

## New version

`0.4.0`

## Reason

Evolve LearningOps from a monolithic study-oriented runtime into a modular, evidence-driven Human–AI learning operating system with explicit role isolation, domain Planners, cross-domain learner management, durable Workspace semantics, safe automation and a portable Cockpit adapter.

## Main changes

- formal Learning Method with Socratic, retrieval, spacing, interleaving, Pareto Two-Pass, problem-based, deliberate, adversarial, transfer and metacognitive methods;
- adaptive operational cycle `ORIENT -> MAP -> LEARN -> RETRIEVE -> APPLY -> DESIGN -> DEFEND -> STRESS -> DEBUG -> DEEPEN -> CONNECT -> REFLECT -> REVISIT`;
- Competency Model, Curriculum, PDI, Mastery, Knowledge Graph, Professional Profile and Evidence-Based Resume specs;
- Generative AI Architecture spec with Single Responsibility, role isolation, context engineering, capability honesty and eval-driven development;
- Evaluation spec expanded for runtime regressions;
- new Learning Planner spec and schema;
- new Workspace Runtime spec for Proactive Consentful Persistence and no-chat-memory durable state;
- new Automation spec with daily Workspace Maintenance and weekly Health Review defaults;
- new ChatGPT Sites Cockpit adapter spec and Cockpit configuration schema;
- three-surface ChatGPT topology: `LearningOps OS`, `My Learning`, and naturally named study chats;
- bilingual PT-BR/EN onboarding and user-facing runtime behavior;
- first-message capability discovery for all three chat types without keyword dependence;
- generic ChatGPT Study Mode disabled by default inside LearningOps study chats, with a future compatibility-eval path;
- global PDI prioritization across domains while preserving domain-local gap context;
- study chat separated from internal session/checkpoint lineage units;
- machine-valid schemas for durable competency, curriculum, Planner, PDI, evidence, mastery, checkpoint, graph and Cockpit records;
- stale `LearningOps-core` naming corrected in affected Core documentation.

## Impact

### Core

Material architecture and methodology change. Specialized specs own separate responsibilities and the Project instruction orchestrates them.

### ChatGPT adapter

Existing LearningOps Projects must replace their Project Instructions with the 0.4.0 canonical `runtime/CHATGPT_PROJECT_INSTRUCTIONS.md` after merge.

Recommended canonical chats:

- `LearningOps OS` — setup, control plane, architecture and maintenance;
- `My Learning` — cross-domain learner state and professional development;
- other chats — naturally named study domains.

### Workspace

No existing learner evidence or mastery values are changed merely by upgrading Core.

The Workspace contract now explicitly supports:

- approved versioned domain Planners;
- cross-domain learner state;
- Cockpit configuration/snapshots;
- proactive consented persistence;
- recurring reconciliation/health review.

A companion Workspace migration/update should add the logical locations required by these contracts without fabricating learner state.

## Migration

### Core migration

- update ChatGPT Project Instructions to the 0.4.0 runtime prompt;
- rename the canonical maintenance chat convention from `Sistema LearningOps` to `LearningOps OS`;
- create/use `My Learning` for cross-domain learner operations;
- retain naturally named study chats.

Existing chat history does not need to be deleted; canonical routing applies going forward.

### Workspace migration

Existing domain/evidence state remains conceptually valid.

Additive structure may include:

```text
domains/<domain-id>/planner/
learner/pdi/
learner/professional-profile/
learner/cross-domain/
cockpit/config/
cockpit/snapshots/
```

Existing compatible paths may remain. Do not move or rewrite historical evidence solely to match a cosmetic layout.

### Evidence compatibility

The evidence schema remains backward-compatible in intent while representing external sources, assistance, confidence, limits, counterevidence, privacy and correction lineage more explicitly.

## Compatibility

- Zero Baseline remains unchanged;
- Evidence Lineage remains unchanged;
- existing evidence/history remains conceptually valid;
- existing domain state can be adopted incrementally;
- old `Sistema LearningOps` chats remain usable as history but the canonical control chat name is now `LearningOps OS`;
- external integrations should load the specialized spec that owns the operation rather than assume monolithic learning-spec behavior;
- ChatGPT Sites is an adapter, not a Core dependency;
- generic Study Mode is not a Core dependency.
